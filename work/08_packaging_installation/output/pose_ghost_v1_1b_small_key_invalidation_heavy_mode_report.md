# V1.1B-small Key-Edit Invalidation + Heavy Rig Mode Report

## Verdict
**Pass**

## What Changed
- Added robust key-edit tracking (`is_stale`, `dirty_reason`, `last_dirty_time`) directly to the core `Controller`.
- Designed a Maya-safe "debounce" pipeline by linking a time-diff check directly into the `idle` event drainage loop, bypassing the need for separate multithreaded timers.
- Added a `Heavy Rig Mode` toggle UI that directly interfaces with the core controller via `set_heavy_rig_mode()`.
- Updated `UpdateQueue` to append requests rather than strictly overwrite, discarding old expensive rebuild requests while safely preserving non-mutually exclusive actions (e.g., UI status updates and targeted cache invalidations).
- Created a `status` label in the UI to present real-time ghost validity state directly above the Target Object inputs.

## Root Cause of Cube Key-Change Stale Cache Bug
Previously, animation edits triggered standard events, but since the snapshot caching mechanism (`GhostNodePool`) keyed heavily on float times and node paths, the cached nodes were retrieved unchanged despite the underlying deformation being different at those target times. The animator manually forcing a rebuild cleared the stale DAG state, but the automatic loop lacked explicit pool invalidation signals upon an animation curve edit. 

## Root Cause of Heavy Rig Unusability under V1 Duplicate Renderer
Heavy rigs like Deadpool have deeply nested deformer hierarchies and complex rig graphs. A standard keyframe edit immediately dirtied the graph; executing mesh duplicates natively triggers full Maya evaluation storms. Doing this automatically upon any key-edit or timeline scrub halts the interface. 

## The Logic According to Codex
The V1.1B-small implementation addresses the required goals iteratively by relying cleanly on the existing `idle` drainage loop:
1. `MayaEventBridge` intercepts a Maya key edit and pushes a `KeyEditEvent(timestamp)` to the controller.
2. The controller marks itself stale, sets an auto-rebuild flag (if Heavy Rig is OFF), and instantly queues UI status updates and a pool cache invalidation.
3. Every Maya idle tick, `check_debounce` verifies if `0.3` seconds have elapsed since the last key edit.
4. If the delay passes, a formal force-rebuild is flushed to the `UpdateQueue`, and finally rendered to the viewport seamlessly. 
5. Heavy Rig Mode completely bypasses setting the auto-rebuild flag while explicitly labeling the UI "ghosts frozen" so the animator acts manually, avoiding graph evaluation spikes.

## What Bugs Could Happen
- Since `GhostNodePool` cache invalidation actively deletes the duplicated geometry nodes, rapid scrubbing on a complex rig with Heavy Rig Mode *off* could generate small stutters during the invalidation deletions.
- If a user rapidly checks and unchecks Heavy Rig Mode alongside key edits, the debounced rebuilds may queue inconsistently depending on precise millisecond timings in the UI event loop. 

## How to Test
1. Set up a simple animated cube. Create ghosts via 'Show Both'.
2. Change a keyframe. Ensure the status turns to `Stale`, then `.3` seconds later automatically rebuilds the new topology to the viewport.
3. Turn on Heavy Rig Mode. Adjust a keyframe. Ensure the status updates to `Ghosts frozen` and no automatic rebuild happens. Click "Force Rebuild" to manually render the new ghosts.

## How this Relates to the Spec / Approved Decision
This completes the V1.1B-small requirements, closing out the explicit pipeline blockers regarding heavy deformers interrupting workflow playback while making sure light topology automatically updates intuitively. The underlying logic respects the core rules to keep logic Maya-agnostic while moving all heavy lifting cleanly into delayed seams. 

## What Could be a V2 Improvement
The definitive V2 improvement for heavy rigs is migrating away from DAG node duplication entirely towards a direct mesh data fetch injected into Viewport 2.0 (`MPxSubSceneOverride`). This would bypass the entire evaluation storm generated by Maya's standard dependency graph when instantiating complex shapes.
